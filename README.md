# Support Ticket Classification

A machine learning project that classifies customer support ticket text into a
**category** and a **priority** using two independent TF-IDF + Logistic
Regression pipelines.

## Project objectives

- Predict the type/category of a support ticket.
- Predict the urgency/priority of a support ticket.
- Compare TF-IDF n-gram and Logistic Regression regularization settings using
  cross-validation.
- Evaluate on a held-out validation set and report accuracy, macro F1, and
  confusion matrices.
- Inspect misclassified examples and save reusable models with Joblib.

## Dataset description

This project uses a **synthetically generated support-ticket dataset** created
by `src/generate_dataset.py`. It is not a collection of real customer messages
and contains no personal customer information. The generator creates ticket
descriptions from documented issue templates, urgency phrases, and closing
phrases so that the full workflow can be reproduced without downloading an
external dataset.

The dataset contains at least 500 rows and the following columns:

| Column | Description |
|---|---|
| `ticket_id` | Unique generated ticket identifier |
| `text` | Support ticket description |
| `category` | Target label describing the issue type |
| `priority` | Target label describing urgency |

Categories: Account Access, Billing, Technical Issue, Shipping, Returns,
Product Inquiry, Subscription, and Security.

Priorities: Low, Medium, and High.

The exact row count and class counts are generated by the preparation script
and saved to `data/processed/dataset_summary.json`. The script also prints the
counts to the terminal. Do not manually assume these counts; report the values
from the generated summary.

## Data preparation

Text is lowercased, trimmed, and whitespace-normalized. Rows missing a target
or text are removed, and duplicate ticket text is dropped. A combined
category-priority stratification key is used to preserve the joint label
distribution across the 70% training, 15% validation, and 15% test splits.

## Modeling approach

Two separate pipelines are trained:

1. `TfidfVectorizer` + `LogisticRegression` for category.
2. `TfidfVectorizer` + `LogisticRegression` for priority.

Grid search uses 5-fold stratified cross-validation to compare unigram vs.
unigram-plus-bigram features and Logistic Regression `C` values of 0.1, 1, 3,
and 10. Macro F1 is the tuning metric.

## Evaluation outputs

- Validation accuracy and macro F1 for each target.
- Classification reports and confusion matrices.
- Ten validation examples ranked for manual review: misclassified examples
  first, followed by the least-confident predictions if the baseline makes
  no errors. Each row includes a reason to investigate.
- Serialized pipelines in `models/`.
- A separate held-out test evaluation.

Metrics depend on the generated data and software versions. The README does
not claim a pre-set accuracy target; use the actual printed validation results.

## Run locally

```bash
# Create and activate a virtual environment (Windows PowerShell)
py -m venv .venv
.\.venv\Scripts\Activate.ps1

# Install dependencies
python -m pip install -r requirements.txt

# Generate the raw dataset
python src/generate_dataset.py

# Clean, summarize, and split the dataset
python src/prepare_data.py

# Tune, validate, save models, and create error-analysis reports
python src/train_models.py

# Evaluate the saved models on the untouched test set
python src/evaluate_models.py
```

## Reproducibility

The dataset generator and split scripts use a fixed random seed (`42`).
Cross-validation is shuffled with the same seed. Re-run the scripts in the
order shown above to reproduce the dataset, splits, models, and reports.
